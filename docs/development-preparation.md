## 入口与运行方式

| 路径 | 用途 | 当前方式 |
| --- | --- | --- |
| `public/index.html` | 导航首页 | 单文件 HTML、内联样式和脚本；Tailwind CDN |
| `server.js` | 本地静态预览服务 | Node.js 内置模块；默认端口 8080，可通过 `PORT` 指定 |
| `blog-src/posts/` | 博客正文 | Markdown |
| `blog-src/templates/` | 博客模板 | Jinja2 |
| `blog-src/build.py` | 博客生成 | Python；当前写死 Linux 项目路径 |
| `public/blog/` | 已发布博客 | 生成后的 HTML 和图片，可直接预览 |
| `scripts/ai-daily-fetch.js` | AI 日报采集 | Node.js、RSS；写入 `public/ai-daily/data/articles.json` |
| `public/ai-daily/` | AI 日报页面 | 静态 HTML 和 JSON |
| `public/sim/` | 原模拟盘页面、脚本与数据 | 独立功能，升级导航时需保留 |
| `public/trading/` | 服务器上留存的交易页面、脚本与数据 | 线上 `/trading/` 实际被 Nginx 代理到端口 8000，不能以本地同路径页面推断现网行为 |

安装 Node.js 依赖：

```powershell
npm.cmd ci --ignore-scripts
```

启动当前源码预览：

```powershell
$env:PORT = '18866'
npm.cmd start
```

访问 `http://127.0.0.1:18866/`。当前服务沿用原代码监听所有网卡地址，退出时停止对应的预览进程。

首页预览无需先生成博客或执行采集、模拟盘和交易脚本。

## 已确定的使用方式

- 正式站点地址为 `https://hooper.ink/`；本地预览仅用于升级检查。
- 导航公开；2026-10-16 新要求将随手记改为私人模块，登录后才能看到内容和图片。
- 仅站主维护内容；公开浏览不等于开放新增、编辑、删除或上传权限。
- 管理入口必须使用密码登录。服务器校验登录会话后，才允许新增、修改、删除、排序和上传；未登录的直接接口请求也必须拒绝，不能仅在前端隐藏管理按钮。
- 首轮收集内容包含文字笔记、链接和图片。
- 本地服务保存导航、私人便笺和图片；浏览器个人收藏与音乐文件另行处理，不把便笺保存到 localStorage。
- 用户要求先参考此前 Demo 再继续确定方案；原型能力、历史产品决定与当前约束的差异记录在 `docs/demo-handoff.md`，不直接视为已批准迁入。
- 最新界面方向：无侧栏、全屏沉浸式；图标暂时保持现状。配色拒绝科技蓝、偏暖及明显偏色的雾灰，要求接近中性的深色、清晰明亮的文字和明确层次，同时避开纯黑、纯白。已选定深石墨并应用到 `preview-1080/` 本地预览，工具移至顶部；1920×1080 和 1920×900 均验证一屏无滚动。线上没有替换，详细范围见 `preview-1080/README.md`。

## 桌面首页的一屏要求

- 用户要求以完整 1080p（1920×1080）为桌面设计标准：导航首页不翻页，不产生横向、纵向或面板内部滚动，所有首页信息在同一屏内呈现。
- 按浏览器缩放 100% 设计；验收时同时记录系统缩放和实际页面视口尺寸。1080p 屏幕还会被浏览器工具栏、窗口边框和任务栏占用，应按实际可用区域排布，不能要求进入全屏模式才满足要求。
- 现有 24 个导航条目在“全部”状态同时可见，不通过翻页或切换分类才能访问其余条目。
- 保持正常可读的文字与操作尺寸；不能靠整体缩小页面或裁掉内容达成一屏。
- 首页需同时容纳站点身份、天气、诗词、搜索、分类、网址、收集区、主题切换、管理入口和必要页脚信息。
- 长笔记、图片与持续新增内容存在有限屏幕容量约束：摘要/附件展示并点开查看，或全文展示并限制数量和长度，等待用户确定。不能默认用内部滚动、分页或隐藏超量内容处理。
- 手机体验单独设计；本条桌面标准不自动等同于手机也能展示同等数量内容。
- 后续验收记录页面与各内容区的实际边界、横向和纵向溢出，以及所有既定首页内容是否完整可见。

当前空间占用：主区域最大宽度为 1280px，顶部诗词和搜索纵向堆叠，桌面网址为 4 列，24 条形成 6 行，页脚还带有较大的顶部留白。下一阶段优先重排这些区域。

布局草案：上方紧凑排列站点信息、天气、诗词和搜索；主区域以网址导航和收集区并排，增加网址列数，底部压缩为一行必要信息。具体列数和高度需要按实际视口及收集内容展示规则验证，当前未修改首页。
